# 在编码智能体中使用 Jev

> 使用编码智能体时，Jev 是什么（以及不是什么）。

如果你是在为编码智能体寻找可插拔的模型时发现 TypeSafe 的，请从这里开始。Jev **不是** Claude Code、Cursor、opencode、Copilot、Muse Spark、Grok Bot 或类似工具背后 LLM 的直接替代品。相反，你可以像往常一样使用你的编码智能体编写代码，让这些代码使用 Jev 来做决策。

## Jev 不是聊天或代码补全 LLM

Jev 是一个 [System One 模型](/concepts/system-one)。它不生成文本、不写代码、不进行对话。它接收一个[状态](/concepts/state)和一组类型化的[问题](/primitives)，返回代码可以直接使用的结构化答案：

* 从选项列表中选出的一个 `choice`，附带每个选项的概率。
* 按你定义的量规给出的一个 `score`。
* 一个针对真/假陈述的 `noul`（0–1）。

编码智能体依赖能够流式输出文本、调用工具、根据自然语言指令编辑文件的 LLM。Jev 不做这些事。不存在 `model: "jev-latest"` 这样的设置能把你的编码智能体变成 Jev 驱动的智能体，因为这两个系统解决的是不同的问题。

## 你可能想要的是什么

选择与你意图相符的那一行：

| 你想做的                                                                                                            | 应该这样做                                                                                                                                                                                                                                                                                            |
| ------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 让你的编码智能体更擅长*编写使用 TypeSafe 的代码*                                                                     | 安装 [TypeSafe 智能体技能](/agent-skill)。它为 Claude Code、Codex 等智能体提供 Jev API、[原语](/primitives)和[模式](/patterns)的完整上下文，让它们为你生成正确的 TypeSafe 集成代码。                                                                                                                |
| 在你正在构建的应用或智能体中使用 Jev——用于路由、分类、评分、护栏或任何结构化决策                                       | 从[快速开始](/introduction/quickstart)入手，然后阅读[如何用 TypeSafe 构建](/concepts/how-to-build-with-system-one)和[模式](/patterns)，了解[置信度路由](/patterns/confidence-routing)、[意图路由](/patterns/intent-routing)等常见架构。                                                 |
| 替换或更换驱动编码智能体的模型                                                                                       | Jev 不适合这件事。继续使用基于 LLM 的编码智能体，在产品需要快速、校准、结构化决策的地方单独使用 Jev。                                                                                                                                                                                                  |
| 在写任何代码之前先试试 Jev                                                                                           | 打开 [Playground](https://console.typesafe.ai/playground)，粘贴一段文本作为状态，添加几个问题。操作指引见[快速开始](/introduction/quickstart)。                                                                                                                                                        |

## 什么时候该用 Jev

尽管 Jev 不是编码智能体的 LLM，在你用编码智能体构建的智能体或应用*内部*，它往往恰好是正确的工具。当你的代码需要以下能力时，选用 Jev：

* 把请求路由到一组固定目的地中的一个，并知道这次路由有多大把握。
* 按量规（紧迫性、质量、风险）给某物打分，并基于数值做分支。
* 在采取行动之前，检查某个陈述对文档、消息或记录是否为真。
* 用一个天生就返回类型化值的调用，替换要求 LLM"返回 JSON"的脆弱提示词。

如果以上任何一条符合你在构建的东西，最快的入门路径是[快速开始](/introduction/quickstart)，然后是各问题类型的[原语](/primitives)参考。
