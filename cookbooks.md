# Cookbooks

> 端到端实战 recipe，展示 TypeSafe 在真实问题中的用法：从几个问题，到完整流水线。

每篇 cookbook 都是一个完整实例：一份真实数据集、一组针对它做出判断的 TypeSafe 问题，以及把这些判断变成可用系统的代码。想在具体问题上看到[原语](/primitives)与[模式](/patterns)怎么配合，就读一篇；想拿它当自己项目的起点，就抄一篇。

本节假设你已经了解 [TypeSafe 原语](/primitives)，也理解[置信度是怎么工作的](/confidence)。如果还没有，请先读那两篇。

## 自一致性

把同一个判断重复多次，用多次运行之间的一致程度作为信号。

| Cookbook                                                            | 做什么                                                                                                            | 难度 |
| ------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- | -------- |
| [自一致性：noul](/cookbooks/consistency_noul_cookbook)              | 把概率上不确定的判定交给人工复核，同时保留底层的 noul 数值可见。                                                  | 入门 |
| [自一致性：choice](/cookbooks/consistency_choice_cookbook)          | 在审核决策里增加一个「不确定」结果，并把标签一致率与自动处理占比放在一起对比。                                    | 入门 |

## 批处理

把大量问题打包进一次请求。

| Cookbook                                            | 做什么                                                                                                                                                                                     | 难度 |
| --------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------- |
| [并行问题](/cookbooks/parallel_questions)           | 对 GDPR 维基百科条目运行一份 13 个问题的合规简报，证明把所有问题打包进一次 TypeSafe 调用后便宜 12.2 倍、快 10.0 倍，而答案没有任何变化。 | 入门 |

## 操作指南

常见任务的做法：检索、格式化、工具选择、护栏。

| Cookbook                                                        | 做什么                                                                                                                                                                                                             | 难度        |
| --------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------ |
| [重排](/cookbooks/rerank_typesafe)                              | 为 40 条 CLERC 法律查询构建 30 个段落的 BM25 候选列表，再对每个「查询-候选」对提一个 TypeSafe 问题，把 top-1 准确率从 5% 提升到 18%，top-10 准确率从 38% 提升到 62%。                       | 入门     |
| [逐行搜索](/cookbooks/semantic_find)                            | 为 GitHub 服务条款构建语义搜索。一次请求里用 Choice 问题给 218 个行号与一句大白话查询打分，再用 Noul 问题检查文档中到底有没有答案。 | 入门     |
| [结构恢复](/cookbooks/autoformat)                               | 用两次请求从丢失格式的纯文本重建 Markdown：一次把硬换行的行重新接回句子，一次给每个块（标题、列表、代码、提示块）分类。                                | 入门     |
| [函数调用](/cookbooks/function_calling)                         | 把自然语言的交易请求变成对普通类型化函数的调用：把函数名与封闭取值集合的参数映射成带置信度的 TypeSafe 问题。                                                | 进阶 |
| [技能推荐](/cookbooks/skill_suggestion)                         | 从 Nous Research 的 Hermes 目录里的 182 个技能中，为一次智能体回合挑出至多一个技能，用两次 TypeSafe 请求给靠前的候选排序并复核。                                                         | 进阶 |
| [知识图谱实体对齐](/cookbooks/entity_alignment)                 | 判断来自两份啤酒目录的 450 个候选对里哪些指的是同一款产品：用一个 Score 问题加三个配套 Noul，后者指出是哪些字段不一致。                                          | 入门     |
| [对 RAG 段落分类](/cookbooks/classifying_rag_passages)          | 用一次 TypeSafe 请求给每个检索回来的段落打分，再由代码决定哪些段落进入答题模型。                                                                                                        | 进阶 |
| [复核引用](/cookbooks/citation_check)                           | 对照源文档检查，抓出错误或凭空捏造的引用。一个 Choice 问题判断引文的上下文是否支持该论断。                                                               | 入门     |
| [面向 LLM 的护栏](/cookbooks/llm_guardrails)                    | 用一次 TypeSafe 请求筛检进出 LLM 应用的每条消息，对危害概率与严重程度设阈值，决定放行、复核、拦截还是路由。                                                        | 进阶 |

## 抽取

从杂乱文本里取出类型化的值。

| Cookbook                                                                       | 做什么                                                                                                                                                        | 难度        |
| ------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------ |
| [SDE 级联](/cookbooks/sde_cascade)                                             | 用两阶段的结构化数据抽取级联（mini → verify → reasoning），以一小部分成本拿到大推理模型的大部分质量。        | 进阶 |
| [日期抽取](/cookbooks/date_extraction_cookbook)                                | 通过向 TypeSafe 询问文档中点名的各个部分来抽取绝对日期与相对日期，再在代码里解析与校验，并依据置信度决定是否人工复核。 | 入门     |
| [预解析值抽取](/cookbooks/pre_parsed_value_extraction_cookbook)                | 用正则找出候选的邮箱、电话号码和金额，再让 TypeSafe 选出所要的那一段，使代码能对原文值做规范化。              | 入门     |

## 分类

把输入分到任意深度的类别里。

| Cookbook                                                                      | 做什么                                                                                                                                                                             | 难度        |
| ----------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------ |
| [层级分类](/cookbooks/hierarchical_classification)                            | 借助 TypeSafe Choice 概率上的并行束搜索，把文档分类进很深的专利、零售商品、生物医学和源代码层级。                         | 进阶 |
| [AutoResearch 特征发现](/cookbooks/autoresearch_feature_discovery)            | 跑一个 autoresearch 循环：自己提出 TypeSafe 问题、把自由文本转成数值特征，再用模型误差来改进一个有监督的 CatBoost 回归器。                  | 高级 |
| [用置信度做分类](/cookbooks/classification_using_confidence)                  | 用一个 Choice 把 SEC 年报分类到 75 个行业组，再读取答案自身的置信度，决定是报告该组，还是报告它上面更宽的部门。 | 入门 |
